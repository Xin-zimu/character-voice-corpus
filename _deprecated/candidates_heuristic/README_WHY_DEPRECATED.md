# 这个目录为什么被废弃

**一句话：它不是"信噪比偏低的素材"，而是"信号定义错误的产物"。直接不要用，不要降级使用。**

废弃日期：2026-10-21
原脚本：`scripts/_deprecated_heuristic_filter.py`（原 `nagato_filter.py`）

---

## 原假设

长门的台词在文本层面有强特征：极短（2–6 字）、句末只有句号和省略号、
少有语气助词、不常自称"我"。

所以：先按这些特征打分，得到"高置信候选池"，再在小池子里精判。
听起来合理，**但假设是错的**。

## 实测结果

- 全量 13070 条 → 筛出 1118 条（8.6%）
- 人工抽查精度约 **15%**
- 更糟的是：错误**不是随机分布**，而是系统性的

### 错误模式一：奖励短句 → 同时命中三类人

这部作品的短句分布是这样的：

| 谁 | 短句类型 | 例子（均真实命中候选池） |
|---|---|---|
| 阿虚 | 第一人称内心独白，短而平淡 | `…那倒不是`（s7，最高分） |
| 朝比奈实玖瑠 | 短 + 软 + 充满犹豫 | `呃…还是不明白`（s6）、`其实不大明白`（s6） |
| 春日 | 祈使短句 / 喊人 | `我才不要是也`（s5）、`哟 阿虚`（s6） |
| 长门 | 短 + 平 + 无犹豫 | `可以`、`无所谓`、`请便` |

长门只占其中一小部分。而阿虚是**第一人称叙述者**，全片他的独白量远超长门台词量，
所以候选池里比例最高的其实是阿虚。

s>=6 的 359 条里，`阿虚…` 出现 20 次以上，`朝比奈学姐`、`凉宫同学`、`对不起`
遍地——**这些全是在叫别人，或被别人叫**。

### 错误模式二：信号方向相反

这是最致命的一点：

- 长门 = 短 + **平** + **无犹豫**
- 朝比奈 = 短 + 软 + **充满犹豫**

打分函数只要"短"就给分，于是把两个特征**相反**的角色混为一谈。
更糟的是，长门的"平"在文本上表现为"没有语气词"，
而朝比奈的"软"在字幕里也常常被写成短促加省略号——字面上难以区分。

## 你举的四条噪声（已验证）

| 台词 | 在候选池 | 实际说话人 |
|---|---|---|
| `血止不住` | ep消失 2:15:35，s6 | 阿虚（被朝仓刺伤后） |
| `阿虚  换你做摄影师` | ep03 0:09:13，s5 | 春日 |
| `果然你还是不戴眼镜比较好` | ep04 0:21:38，s5 | 春日（对阿虚说） |
| `我才不要` / `我才不要是也` | ep06 s5 / ep13 s5 | 春日（口头禅） |

如果拿这批数据做 few-shot，最可能学到的不是"长门说话"，而是
"**阿虚的旁白节奏 + 春日的口头禅**"。这比没有示例更糟——它会主动教坏模型。

## 正确的替代路径

```
parsed (L0, 全量)
  → extract_scenes.py  用「长门/有希」称呼锚点定位"她在场的片段"（4316 条）
  → annotate.py        LLM 标注每个片段里哪句是她说的
  → 人工复核
  → labeled (L2)       才可进入 few-shot / 微调
```

关键区别：`scenes` 是"**她在场**"的证据，不是"她说话"的证据。
所以它必须经过标注，不能直接用。但它比字面筛选可靠得多，因为
"别人喊她名字时她在场"是剧情事实，不是文本统计。

## 保留代码的原因

不是留着以后用，是留着当**失败记录**。下次有人（包括未来的自己）想
"先用规则筛一遍省点标注成本"的时候，这份文件应该能拦住他。
